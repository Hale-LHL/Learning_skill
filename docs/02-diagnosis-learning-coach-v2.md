# learning-coach v2 诊断报告 —— 为什么必须重写而不是修补

> 诊断对象：`~/.workbuddy/skills/learning-coach/SKILL.md`（101 行，单文件，无附属资源）
> 诊断日期：2026-11-11
> 结论：**不能修补，必须重写（v3）**。理由见末尾「为什么不能打补丁」。

## 0. 先纠正我自己一个错误判断

在阶段一方案文档里我写过：

> `learning-coach`（v2）…**直接复用为内核**。这部分已经是同类里的高水位，重写等于倒退。

这句话是**基于 skill 的 description 和标题结构推断出来的，不是基于读源码**。实际逐行读完 101 行之后，结论相反：

> v2 的**规则文本**确实写得漂亮（密度高、有文献名、有表格），但它**引用的所有对象都是虚构的**。规则越漂亮，运行时落差越大。

我把阶段一文档里那两处评价一并改掉了（见 §4）。这里记下：**看起来专业的规则文本，和能跑的系统，是两件事。**

---

## 1. P0 问题（存在即失效，不是优化项）

### P0-1 规则引用的对象全部不存在

| 位置 | 原文 | 实际状态 |
|---|---|---|
| §1.1 | 「查欠账清单有没有到期复检项」 | `~/.study-os` 目录不存在，无清单 |
| §3 | 「档案/错题记录优先」 | 无档案文件，无错题库 |
| §8 | 「维护显式欠账清单，每轮开头检查」 | 无清单 |
| §9 | 「每 3~5 个概念让用户自评…当场闭卷抽测」 | 自评结果无存放处，抽测分数无记录 |
| §11 | 「同类问题连续 3 次独立通过 → 自动降档」 | 无计数器，无法判定哪次是"第 3 次" |

**后果**：这四类规则每轮都在"假装查了一个不存在的东西"。模型只能靠当前上下文的模糊记忆临时编，一旦换会话（新 context），全部归零。所以用户体感是——**它每次都在重复同样的开场，没有任何"记得我"的感觉**。

这不是模型的锅，是 skill 设计的锅：**规则层没有数据层支撑，就等于没有规则**。

### P0-2 触发范围失控

frontmatter 的 description 里写了触发词：`解释XX`、`为什么`、`怎么做这题`、`给我答案`。

`为什么` 是中文最高频疑问词之一。后果：装了它之后，

- 「为什么我的打印机连不上」→ 被问「你的版本是什么？」
- 「为什么 A 股今天跌了」→ 被问「你的版本是什么？」
- 「解释一下这个报错」→ 被拖进五步协议

**这是"不满意"最直接的来源**：不是规则不对，是规则**管得太宽**。一个学习陪练技能不应该在用户问天气的时候摆出考官姿态。

### P0-3 硬规则与分层规则直接打架，且硬规则更靠前

- §1.3 说：**「B/C 类问题的第一句话永远是：『你的版本是什么？』」**（绝对化，"永远"）
- §3 说：**「新手 → 完整示范 + 具体例子 + 用户复述」**

场景：零基础用户问「梯度下降是什么」。§1.3 要求先反问，§3 要求先示范。两条指令冲突，而 §1 位置更靠前、用词更绝对（"永远"），模型实际执行时**大概率走 §1.3**——于是一个完全没概念的人被要求"先说你的版本"，只能编一个，或者干脆放弃。

这是「expertise reversal effect」的典型误用：分层判断写了，但被前置的绝对规则覆盖掉了。

### P0-4 三套维度交叉，没有任何优先级声明

v2 同时存在三个分类轴：

- 轴 1（§2）：问题类型 A/B/C/D
- 轴 2（§3）：用户水平 新手/进阶/熟练
- 轴 3（§5）：提示层级 1/2/3/4

三轴交叉后没有裁决表。例如：B 类 + 新手 + 该给第几层提示？无人回答。模型只能临场即兴，于是**同一个问题问两次得到两种流程**，用户感到"不稳定、看它心情"。

### P0-5 闭环是假的

§8「掌握制推进」、§9「元认知对账」、§11「毕业条款」，这三节构成了 v2 宣称的"闭环"。但没有一处定义：

- 抽测怎么评分（几档？谁来评？标准是什么？）
- 分数存哪
- 分数如何影响下一次调度
- 什么算"独立通过"

**没有定义 = 无法执行 = 闭环不存在。** 这正是阶段一文档里 PNAS 2025 数据的教训：光有引导不产生收益，收益来自可测量的复习调度。

## 2. P1 问题（影响体验与任务达成）

### P1-1 零错题能力（用户三大核心需求之一）
v2 全文涉及错题只有 §4.5 的「入卡」两个字。没有：错因分类法、同类题生成、二刷验证、错题统计。

### P1-2 零电子书 / 零可视化能力（用户三大核心需求之一）
完全没有。用户明确要「把电子书内容做成结构清晰的可视化板块」，v2 一个字没有。

### P1-3 事实性知识不要求来源（用户明确要求）
v2 §2 对 A 类查事实型的处理是「直接答，不折腾」。用户的要求是「事实性知识可以给，但**要附来源链接**」。v2 缺失这条，等于允许模型随口报数字。

### P1-4 提示阶梯只有名词，没有句式
§5 的四层是「指向层/框架层/半成品层/完整层」——这是**分类**，不是**话术**。执行时模型看到"指向层"三个字，自由发挥出一句话，质量完全随机。缺一个可直接抄的句式库。

### P1-5 驳回手册只有拦，没有"什么时候不该拦"
§10 列了 6 种要驳回的说法，但没有任何逃生阀：用户明天要考试、用户已经挣扎 40 分钟、用户明确说"这次只要答案，我知道自己在偷懒"。没有逃生阀的强制规则，长期使用会被用户**直接绕过**（关掉 skill、换个 AI）。

## 3. 为什么不能打补丁

修补意味着在 101 行基础上加数据层、加优先级表、加句式库、加错题模块、加电子书模块、加来源要求、加逃生阀。粗算会到 350+ 行。

而 SKILL.md 是**每次触发都全量加载**的。350 行的硬规则会挤占上下文、稀释注意力，且各条规则互相竞争执行优先级。

**更关键的是**：v2 的根本缺陷不是「缺几条规则」，而是**规则层悬空于数据层之上**。补丁只能再糊一层规则，解决不了悬空。

所以：**重写为 study-os（系统层）+ learning-coach v3（对话层薄壳）**。

## 6. 自检：这份诊断本身有什么问题

**Q：你是不是在给重写找理由？v2 真有这么差？**
A：部分是。v2 的**规则内容**质量确实高——四类分流、五步协议、四层阶梯、驳回清单，这些在 v3 里我一条都没丢，全部继承并补上可执行细节。差的不是想法，是落地。所以"重写"的准确含义是：**规则思想保留，执行架构推倒**。

**Q：P0-3 说"新手会被反问劝退"，可你不是主张先要用户版本吗？**
A：主张"先要用户版本"，前提是用户**有版本**。零基础用户没有版本，问他要版本等于问他要他没有的东西。v3 的裁决表里写死了：新手 × B 类 → 先给最小示范（含一个具体例子）→ 立刻要求复述 → 再进五步。这是修正，不是放弃。

**Q：诊断里说"数据层缺失"，可 SKILL.md 本来就不该存数据吧？**
A：对，SKILL.md 不该存数据。但**规则可以且必须指明数据在哪**。「查清单」这句话必须配一个 `review.py due` 的真实调用；不配就是空话。这不是要求 SKILL.md 存数据，是要求规则可执行。
