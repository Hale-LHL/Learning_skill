## 2. 证据底座：学习科学到底说了什么

### 2.1 三大支柱的效应量（这是一切规则的根）

| 方法 | 效应量 | 来源 |
|---|---|---|
| **检索练习**（闭卷自测/主动回忆） | g = 0.50（Rowland 2014）；**加反馈后 g = 0.73**；综合 g = 0.61（Adesope 2017）；课堂场景 g = 0.50（Yang 2021） | [PMC 综述](https://pmc.ncbi.nlm.nih.gov/articles/PMC12292765) / [效应量汇总](https://memormore.app/blogs/spaced-repetition-research) |
| **间隔重复** | g = 0.74（Latimier 2021）；课堂 d = 0.54（Mawson & Kang 2025）；d = 0.46（Donovan 1999） | 同上 |
| **交错练习**（混着练） | g = 0.42（Brunmair & Richter 2019），**但 I² = 77%，异质性极高** | [PMC: No Simple Solutions](https://pmc.ncbi.nlm.nih.gov/articles/PMC10950551/pdf/10.1177_23727322231218906.pdf) |
| 自我解释 | d ≈ 0.30–0.60（Chi 1994 起） | [证据分级汇总](https://problemory.com/bm/blog/evidence-based-learning-techniques-ranked) |
| 追问式精加工（"为什么"） | d ≈ 0.30–0.50 | 同上 |

**两个必须记住的细节**：

1. **交错练习不是万灵药**。同一篇综述明确列出反例：概念容易区分但难以整合时、规则难以言说时、技能需要同时关注多个部件时（如学不同球类动作），**分块练习反而更好**。所以 skill 里不能无脑"打乱"，要按条件判断。
2. **最优间隔 ≈ 目标保留期的 10–20%**（Cepeda et al. 2008，1354 人）；若目标是记住一年，间隔缩到 5–10%。这给了复习调度一个可计算的公式，而不是凭感觉抄"1/2/4/7/15/30"。

### 2.2 PNAS 2025 那个实验，完整读一遍（这是本方案的核心依据）

来源：[PNAS 原文](https://www.pnas.org/doi/10.1073/pnas.2422633122)｜[详细数据拆解](https://edtechdev.github.io/aied/articles/generative-ai-guardrails-harm-learning)

- 土耳其一所高中，近 1000 名数学学生，约 50 个班，随机分组：无 AI / GPT Base（普通 ChatGPT 界面）/ GPT Tutor（提示不给答案 + 教师预置的正确解与常见错误）
- 每组：教师讲授 → AI 辅助练习 → **无工具闭卷考试**（同概念不同题）

| 组 | 练习成绩 | 闭卷考试成绩 |
|---|---|---|
| GPT Base | **+48%** | **−17%**（比从没用过 AI 的还差） |
| GPT Tutor | **+127%** | **≈ 0**（统计不显著） |

**这里有三个反直觉结论，直接决定 skill 的设计**：

1. **"不给答案只给提示"能止损，但不能提升。** 大多数人（包括我原来那个 learning-coach）默认"引导式 = 更好"。数据是：引导式只是把 -17% 拉回到 0，**没有产生任何正向收益**。
   → 所以"我不告诉你答案"本身**不够**。真正产生增益的是**闭卷检索 + 间隔复现 + 反馈**，引导只是防止伤害的地板。
2. **学生感觉不到自己学坏了。** GPT Base 组考试更差，但自我报告"没觉得学得更少"；GPT Tutor 组**以为自己考得更好**，实际与对照组没差别。
   → 所以 skill **不能依赖你的自评**。必须内置客观测量（闭卷得分、复述完整度、二次错误率）。
3. **伤害的主因不是 AI 答错（它只对了 51%），而是"抄答案"这个行为。** 错误分析与考试表现没有溢出关联，行为分析才是。
   → 所以拦截的重点是**行为**（"帮我把这段写完"），不只是内容。

### 2.3 可视化/总结类方法，证据等级比你想的低

Dunlosky et al. 2013（*Psychological Science in the Public Interest*）评了 10 种学习技术，只有 **practice testing** 和 **distributed practice** 被评为「高效用」；**summarization、highlighting、rereading、keyword mnemonic** 都是「低效用」。

思维导图/概念图**没有**被评到与检索练习同量级的效用，相关研究多为小样本、结论不稳（**待核**，我不给具体效应量，避免编数字）。

**这不代表可视化没用，而是它起作用的方式被误解了：**
- 图的价值不在"看图"，而在**画图这个生成动作**逼你做结构化提取；
- 一旦图是 AI 画好给你看的，你就从"生成者"变成"消费者"，价值大幅流失。

→ **硬规则**：电子书可视化必须走「**先闭卷回忆章节骨架 → 再看 AI 生成的结构图 → 用图反向出题考你**」。图是**检验工具**，不是**阅读替代品**。

### 2.4 被夸大的东西（写进 skill 的"辟谣"条款）

| 流行说法 | 实际情况 |
|---|---|
| 学习金字塔（听讲 5%、教授他人 90%） | 数字源自 1960 年代未发表的二手材料，**无实证基础**。「教别人有效」这个方向对，但具体百分比是编的 |
| 一万小时定律 | Ericsson 原文是"平均约 1 万小时"，不是门槛；Macnamara 2014 元分析：刻意练习只能解释游戏 26%、音乐 21%、体育 18%、**教育仅 4%** 的表现方差 |
| 左右脑/学习风格（视觉型/听觉型） | 无可靠证据支持"按学习风格匹配教学能提升成绩" |

skill 里必须能识别并纠正这类说法——这本身就是"教你不要依赖二手结论"的示范。

## 3. 社区实操调研（B站 / 小红书 / YouTube / GitHub）

### 3.1 中文社区：错题本的真实做法

搜下来，中文教育圈对错题本的共识高度一致，且**都在骂"抄题式错题本"**：

- **北京教育考试院**（[原文](https://www.bjeea.cn/html/ksb/zhongzhaozhuanban/2025/1119/87636.html)）：「改、析、复」三步。核心是"简化记录，聚焦过程"——不抄整题，只记**题目来源 + 关联考点 + 错误原因**。错误类型分三类：**知识型 / 习惯型 / 思维型**。
- **三栏错题法**（[学通在线](https://www.xuetong.com/article/267)）：第一栏错因归类，第二栏正解思路（用自己的话写"我这一步为什么错"），第三栏同类题巩固。**"这一栏最容易被省，但最值钱"**。
- **销号机制**（[练习网](https://www.jslx.com/wmkj/lxzx/5345.html)）：每道错题处理完标记"待复核"（**7 天后**），遮住答案重做，做对且能讲清思路才销号；连续两轮通过可移出。错题本应该**越写越薄**。
- 一个细节很实用：连续两周重做都正确的题，**划掉不再看**——避免错题本变成心理负担。

### 3.2 中文社区：引导式 AI 家教 prompt 的成熟套路

- [Socratic 学习搭子 prompt](https://aitoolsguidebook.com/zh/articles/study-buddy-prompt-ai)：给了我一个很好的结构——开场先收集"当前理解 / 想要的深度 / 已怀疑的盲点 / 时间预算"，然后硬规则：一次一题、答错只给指向提示、半对就追问到暴露盲点、"不知道"就给更小的子问题、**至少试过 2 次才允许揭晓答案**、答对就升级难度或改条件。
- [中国远程教育 I-Socratic 论文](http://cjde.ouchn.edu.cn/EN/Y2024/V44/I6/13)：提出 AIGC 在苏格拉底对话里有三种角色——**引导者**（提问）、**扮演者**（扮演不懂的学生让你讲）、**慧答者**（接受你的反问）。第三种是你原来的 skill 没有的，值得加。
- [iThome 四阶引导策略](https://ithelp.ithome.com.tw/m/articles/10422364)：澄清定义 → 拆解步骤 → 反思验证 → 抽象归纳。且强调要用**状态机**控制提问深度，而不是让模型自由发挥。

### 3.3 YouTube / 英文圈的方法论共识

检索到的英文侧材料与中文高度收敛，主要贡献是**效应量**和**反例条件**（见 §2）。额外收获两条：

- **"productive failure"（先失败后教学）**：2021 年 *Review of Educational Research* 汇总 53 项研究，先尝试再讲解整体优于先讲解再练习，中等效应；**但小学 2–5 年级反过来**。→ 说明"先让你挣扎"这条规则**有年龄/水平边界**，不能对完全新手硬套。
- **retrieval practice 的最强形式是 free recall（自由回忆）**，不是选择题；选择题容易"认出"而非"想起"。

### 3.4 GitHub 上可直接用的轮子

| 项目 | 用途 | 是否采用 |
|---|---|---|
| [markmap](https://markmap.js.org/) | Markdown → 可交互思维导图（单文件 HTML，支持 LaTeX） | ✅ 采用（书库导出用，`npx markmap book.md`） |

## 4. 方案抉择：三个候选

### 方案 A：把 `learning-coach` 扩写成全能 skill
- 做法：在现有 13 节基础上加"错题本""书库""复习队列"三章
- ✅ 单一入口，不会触发冲突
- ❌ 文件会膨胀到 400+ 行，每次对话都要加载全部规则，**token 成本高、注意力稀释**（认知负荷理论对模型同样适用）
- ❌ **已证伪**：v2 读完发现引用的数据对象全部不存在（见 02 诊断），大改不是"有风险"，而是"必须"

### 方案 B：新建 `study-os` 作主编排层，`learning-coach` 降级为触发壳 ★已采纳
- 做法：`study-os` 承担**全部规则 + 数据 + 脚本 + 工作流**，是唯一真相源；`learning-coach` 的 SKILL.md 缩为薄壳，只保留既有触发词并指向 `study-os`，避免同一规则在两处漂移
- ✅ 职责分离，各自可独立迭代
- ✅ 单一真相源：改 `study-os` 一处即生效，不会出现两份规则打架
- ✅ 你原有的"陪练/引导我"等触发习惯继续有效
- ✅ 触发冲突显式解决：`learning-coach` 不再定义任何规则，只做转调

### 方案 C：只做离线流水线（错题/电子书 → 产物），对话引导完全交给 `learning-coach`
- 做法：study-os = 一堆脚本，输入错题截图/EPUB，输出诊断报告和结构图
- ✅ 最省事，见效快
- ❌ 没有解决"持续追踪掌握度"的核心问题，还是碎片化
- ❌ 与你"让我自己学到知识"的诉求错位——产物再漂亮也不等于学会

**裁决：选 B。** 理由：你的真痛点是**没有闭环**（学了→忘了→不知道忘在哪），而闭环需要「数据 + 调度 + 客观测量」，这三样只能靠一个新的编排层承载，不能靠扩写对话规则实现。

## 5. 推荐方案 B 的模块设计

### M1 错题诊断机（Error Lab）

**输入**：错题（截图/文字/拍照）、你的原始解法
**硬规则**：**绝不先给正解**。先让你做三件事。

**快慢双轨（防止流程太重被弃用）**：

| 模式 | 触发 | 走哪几步 | 耗时 |
|---|---|---|---|
| 快轨 | 你说"先记一下 / 快速登记" | 只做 L1 归因 + 入卡（记下考点和错因标签） | 30 秒 |
| 慢轨 | 你说"仔细看这题" / 考前复盘 | 走完整六步 | 5–10 分钟 |

默认走慢轨，但**允许你随时降级**。中文教育圈的错题本失败案例几乎都是"形式大于内容"，双轨是防这个。

流程：
1. **重述题意**（你用自己的话说这题要什么）→ 检验是"思维型错误"还是"没读懂"
2. **复现错路**（你把当时怎么想的写出来）→ 只有知道错在哪一步，才能归类
3. **三层归因**（按中文教育圈共识 + 可计算化改造）

| 层 | 问题 | 归类 |
|---|---|---|
| L1 知识 | 这个考点在教材哪一章？定义能不能复述？ | 知识型 / 理解偏差 / 方法不熟 |
| L2 过程 | 错在审题、计算、还是思路选择？ | 习惯型 |
| L3 元认知 | 当时你觉得自己会吗？ | 若"以为会但错"→ 高危，标记为**胜任错觉** |

4. **只给靶向提示**（指向断点，不给答案；遵循 learning-coach 四层阶梯）
5. **你自己改对后**，生成 2 道变式题（改条件/改问法/反向问）→ 当场闭卷做
6. **入卡**：写入 `error-book.jsonl`，标 `next_review = 今天 + 7 天`

**输出物**：一份 `错题卡.md`（不是抄题，是"考点+错因+一句话纠正+变式题"）

> 关键设计：**错题本要越写越薄**。同一考点连续两次闭卷通过 → 自动标记 `mastered`，不再出现在复习队列。

### M2 电子书结构化可视化（Book Atlas）

**输入**：EPUB / PDF / 你自己粘的章节文本
**流程（顺序不能变）**：

| 步 | 谁做 | 做什么 |
|---|---|---|
| 1 | 脚本 | `pymupdf4llm` / `ebook2md` 抽出 Markdown + 章节树 |
| 2 | **你** | **闭卷回忆**：合上书，说出这章的几个主干（写在对话里，允许错） |
| 3 | AI | 生成结构图（`show_widget` 出 SVG，或 markmap/mermaid），**并标出你漏掉的节点** |
| 4 | AI | 用图**反向出题**：3 道"图里这两个分支什么关系"的题 |
| 5 | 你 | 闭卷答，错的地方回到原文 |
| 6 | 脚本 | 导出 `atlas/<书名>.md` + `atlas/<书名>.html`（可交互思维导图） |

**例外：零基础章节**。productive failure 的 2021 年元分析显示，小学阶段"先讲解后练习"反而更好；对完全没概念的新领域，硬让你先回忆就是空转。规则：**先给 3 分钟概览（只说这章要解决什么问题），再闭卷回忆**。

**反模式（禁止）**：你发一本书 → 我直接吐一张漂亮的全书导图。那是把"生成"外包了，收益接近零。

**图的选型规则**：
- 层级/目录 → markmap（思维导图）
- 机制/流程/因果 → Mermaid flowchart
- 对比/权衡 → 双面板 SVG
- 超过 40 个节点 → 拆成"总览图 + 分章图"，别画成蜘蛛网

### M3 苏格拉底问答（Socratic Router）

**先分流（沿用 learning-coach 的四类，但补一类）**：

| 类型 | 待遇 | 变化 |
|---|---|---|
| A 事实型 | 直接答 + **必须附来源链接** | 新增引用规范 |
| B 概念型 | 五步协议 | 沿用 |
| C 解题型 | 四层提示阶梯 | 沿用 |
| D 情绪/规划 | 正常陪聊 | 沿用 |
| **E 求验证型**（"我这个理解对不对"）| 先让你讲完整版，再逐句批改 | **新增**（这是你最高频的场景，原 skill 只有 B/C 覆盖不好） |

**事实型答案的引用规范**（回应你的"要附来源链接"）：
- 优先级：**原始论文 / 官方文档 > 权威教材 > 二手博客**
- 必须区分三档：`[已核实]`（我打开过并读到原文） / `[模型记忆·待核]`（我凭训练数据说的） / `[有争议]`（学界未定论）
- 公式：**给公式本身 + 一句"这个式子从哪来" + 一个可验证的链接**，然后**反问"你觉得为什么会有这一项"**
- 查不到就明说"查不到"，不编链接（这是硬底线）

### M4 复习调度（Review Engine）

**算法（可算，不凭感觉）**：
```
下次间隔 = 上次间隔 × ease
ease 初始 2.5
答对且能讲清思路 → ease += 0.1，间隔 × ease
答对但讲不清     → 间隔不变（不许涨）
答错             → ease -= 0.2，回到上一档
连续 2 次通过 → mastered，移出队列
```
**上限约束**：间隔不超过「目标保留期 × 0.2」（Cepeda 2008）。若目标是期末考（还剩 60 天），间隔封顶 12 天。

**交错规则**：复习队列默认**打乱学科混合**（交错 g=0.42）；但以下情况保持分块：
- 你明确说"这个考点我刚接触"
- 两个考点容易混淆且你还没分清（此时先分块辨析，再交错）

**每次会话说第一句先查欠账**：有没有到期复检项 → 有就先突击抽测（learning-coach §1 已有，此处强化为"必须调脚本查"）。

### M5 学习仪表盘（Calibration）

**目的：对抗"感觉自己学会了"。** PNAS 证明这个错觉是真实且顽固的。

三张表：
1. **掌握度表**：每个考点 → 闭卷通过次数 / 变式题正确率 / 上次复习日期
2. **校准表**：你自评"会" vs 实测"会"的偏差。**自评会但实测不会 = 胜任错觉，强制降档回炉**
3. **错误分布**：按 L1/L2/L3 归因统计，看你的错是"知识缺口"多还是"习惯性失误"多

每 3–5 个概念做一次对账（沿用 learning-coach §9，但升级为**要有数据**，不能只靠记忆）。

## 6. 关键规则清单（将来写进 SKILL.md 的硬条款）

1. 任何时候，**答案（正解）在最后一屏出现，且出现时用户是闭卷的**。
2. 用户说"直接告诉我" → 一句点破 + 给替代问法，不长篇说教。
3. 事实型答案必须带来源，且标注核实等级；**不确定就说不确定**。
4. **绝不用"我觉得你理解了"作为通过判据**，只认闭卷表现。
5. 电子书/资料 → **先让用户回忆，再给结构图**；图必须配反向出题。
6. 用户一次甩 10 道题 → 只做 1 道完整流程，其余排队。
7. 同一考点连续 2 次闭卷通过 → 主动说"这个可以销号了"（**允许遗忘已掌握的**，避免负担）。
8. 出现"我明明会但做错了" → 标记胜任错觉，进入 L3 元认知追问。
9. 每轮开头查到期复习项，有就强制抽测。
10. 不替用户改文件、不替用户写代码（沿用 ml-concept-explainer 里你自己定的规矩）。
11. 引用二手结论时主动标注"这是二手"，并示范怎么回溯源文件。
12. 不制造"努力的幻觉"：不生成用户没参与的可视化、不产出他没动手的笔记。

## 8. 双模型辩论：怎么把 WorkBuddy 和 DeepSeek Harness 连起来

先给结论：**不用自己写编排，社区已有三套现成方案。**

但先把预期压正确：**多模型辩论不保证产出更好的答案。** 有研究（[2026 年 141 项研究综述](https://www.edgechat.ai/multi-agent-debate)）指出，当前形态的 MAD 系统并不能稳定优于 self-consistency 这类简单方法。所以这条路的价值不是"得到更优解"，而是「**暴露你自己没想到的失效场景**」。如果你的目的是后者，它很划算；如果是前者，可能白花钱。

### 背景（先说清 DSH 是什么）

DeepSeek Harness（DSH）是 DeepSeek 2026-08-13 开源的 Agent 运行时框架，MIT 协议，"一切皆插件"，**不绑模型**（支持近 40 家 provider，含 OpenAI 兼容接口）。定位对标 Claude Code / Codex。
- 官网：https://www.deepseek.com/harness/
- 启动：`npx @deepseek-ai/dsh web`

### 路子 1：`dsh-council`（多模型审议）★最适合"辩论"需求

[插件页](https://dsh-plugin.org/plugins/a1exsun/dsh-council)｜MIT｜156 stars

三阶段：**独立作答 → 匿名互评 → 仲裁**
- 2–8 个模型并行独立回答同一个问题（互相看不见）
- 1–8 个评审匿名比较、挑漏洞、排名
- 仲裁者综合出最终方案，输出**共识 / 分歧 / 盲点 / 置信度**

安装：
```bash
npx --yes @deepseek-ai/dsh@latest plugin --profile web add @a1exsun/dsh-council
npx @deepseek-ai/dsh web
```
用法：在 DSH 对话里敲 `/council`，然后选 作答者 / 评审 / 仲裁，再提问。

**怎么用在你的场景**：把"我这份 study-os 设计"当同一个 brief 发给 WorkBuddy 背后的模型 + DeepSeek-V4，让它们各自挑毛病，再看分歧点。**分歧点就是你要迭代的地方**，共识反而不值钱。

### 路子 2：`dsh-connect-workbuddy`（把你的账号模型接进 DSH）

[dsh-plugin.org 收录](https://dsh-plugin.org/) —— 把已登录的 WorkBuddy 账号接到 DSH，之后**在 DSH 的模型选择器里直接选 WorkBuddy 可用的模型**。

这是"连起来"最直接的字面答案：一个界面，两套模型，同一份上下文。

### 路子 3：`dsh-consult`（第二意见，最轻）

[npm](https://socket.dev/npm/package/dsh-consult) —— 主 agent 干完活，`/consult` 让 2–5 个模型**互不可见**地给独立意见，主 agent 汇总并负责。
- 与 council 的区别：consult 是**检查点式**（只在关键决策触发），council 是**完整审议流程**
- 适合场景：skill 写完了，让它评"这套规则哪里会失效"

### 路子 4：自己写（如果想完全可控）

在 skill 里放 `scripts/debate.py`，用 OpenAI 兼容接口调 DeepSeek：
- 优点：可固化成 skill 的一部分，随时跑"红队评审"
- 缺点：要 API key、要写编排、要自己处理上下文裁剪
- **建议**：先走路子 1/3，确认有价值再考虑自研

### ⚠️ 三条必须知道的风险（有研究支撑）

1. **模型一致 ≠ 正确**。多个模型可能共享同样的训练偏差，一起错。所以辩论产出必须落到**外部证据**上核验。
2. **"有说服力的骗子"**：一个自信但错误的 agent 能把整个共识带偏，准确率可掉 40%（MultiAgent Collaboration Attack）。
3. **社会从众**：agent 会为了达成共识，把对的改成错的（"Talk Isn't Always Cheap"）。
→ 对策：**保留少数派意见**，不要让仲裁者强行抹平分歧；仲裁只给"哪一方证据更强"，不给"哪个答案更受欢迎"。

### 建议的执行顺序

| 步 | 动作 | 预计 |
|---|---|---|
| 1 | 装 DSH（`npx @deepseek-ai/dsh web`，浏览器打开，登录/填 API key） | 15 分钟 |
| 2 | 装 `dsh-council` + 配两个 provider（DeepSeek 官方 + 任意 OpenAI 兼容） | 10 分钟 |
| 3 | 用 `/council` 审本文档 §5 的模块设计 | 20 分钟 |
| 4 | 把分歧点记下来，回来改 skill 方案 | — |

成本提醒：一次 council 涉及 4–17 个模型参与者，每个都可能多次请求。**只在关键决策点用，别每轮都跑**。
