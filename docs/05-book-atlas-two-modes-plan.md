# 啃书模块改造方案：双模式 + 生成前校验

> 记录时间：2026-11-11
> 状态：**模式 A（选择题陪读）已实施；模式 B（生成式）的三件套 + C1–C3 自动校验已实施；C4/C5 仍人工**
> 影响文件：`references/book-atlas.md`（主改）、`SKILL.md`（路由）、`scripts/`（新增质检脚本）
> 起因：用户要求把「啃书」拆成两条路径——**AI 一条一条问** 和 **直接生成文档**，并强调**产出前必须确认内容没有问题、且足够全面**。
>
> **修订（同日）**：用户指出「一条一条来不好输入」→ 模式 A 的提问方式改为**选择题优先**（一次一题、四个选项、回一个字母），并新增 `scripts/check_quiz.py` 把选项规则变成可执行检查。详见 §2.0。

---

## 1. 为什么必须拆成两种

现在的 `book-atlas.md` 只承认一条路：闭卷回忆 → 标差集 → 反向出题 → 交付导图。

这条路的收益最高（检索练习 + 精加工），但它有两个现实约束：

| 约束 | 后果 |
|---|---|
| 需要用户逐章投入 5–10 分钟 | 用户只想快速建立全局认识时不成立，强行走流程会被绕过 |
| 一次只能推进一章 | 一本 300 页书要 3–6 小时，急用场景不适用 |

用户明确要两种，本质是把「**学习**」和「**获取结构**」区分开：

- 要**学会** → 走对话式，一次一个问题，AI 控制节奏
- 要**拿到一份能用的结构化材料**（复习前速览、给同事讲、做笔记底稿）→ 走生成式

**但生成式有个致命风险必须直面**：`book-atlas.md` §0 自己写过——「你发一本书 → 我直接吐一张全书导图，收益 ≈0」。解决方式不是禁止，而是**给生成物加校验 + 加使用约束**（见 §4、§5）。

## 2. 模式 A：AI 一条一条问（对话式啃书）

### 2.0 修订：提问改成选择题

**原始设计的问题**：每章让用户口述三件事（这章解决什么 / 核心定义 / 和上一章的关系），一次一两百字。用户原话是「因为一条一条来不好输入」。真实的失败模式不是学不会，是**第三次就懒得打字，然后绕开这个模块**。

**改法**（详细规则以 `references/book-atlas.md` §2 为准，这里只记决策）：

| 维度 | 改前 | 改后 |
|---|---|---|
| 作答形式 | 口述/打字一段话 | 4 个选项，回 1 个字母 |
| 每章题量 | 3–5 个开放问题 | 4 道选择 + 1 道无选项短答 |
| 选错之后 | 追问偏差那一处 | 先反问「你选的这项在什么条件下成立」，说不清才给最小示范，再让他改选 |
| 诊断力来源 | 我读他的话判断 | **干扰项自带错因标注**（K/M/P/R/T），选错即定位 |
| 质量把关 | 靠自觉 | `scripts/check_quiz.py` 八条规则机器判，E 类不过不许问 |

**为什么不是纯粹的选择题**：选择题考识别，不考回忆（收益打折，见 `evidence.md` §2 新增条目）。所以设两条护栏：每章 1 道无选项题；每 3 章至少 1 次要"说三个关键词"。`check_quiz.py` 的 W6 会专门抓"某章全是选择题"。

**反向开关保留**：把 `quiz.json` 里的 `options` 删掉，整章自动退化为简答题模式。想练得狠的人有路走。

### 触发

用户说「带我啃这本书」「一章一章来」「问我」「别直接给我，让我自己说」；或用户给出书但没说要文档。

### 流程

| 步 | 动作 | 关键约束 |
|---|---|---|
| A1 | 提取目录，只贴**章标题** | 不给内容、不给「本章重点」 |
| A2 | 每章**一次只问一题**（选择题格式），等答完再问下一题 | 不许一口气抛四道；一屏一题 |
| A3 | 答错 → 反问边界 → 最小提示 → 让他改选；答对 → 偶数题追一句「为什么不是 X」 | 不直接念正确答案；改选对了记 `warn` 不记 `ok` |
| A4 | 该章 5 题问完 → 出 30 秒小结，含「你漏了什么」 | 小结是差集表，不是章节摘要 |
| A5 | 掌握度 + 题目 + 每题结果 + 3–5 张检索卡落盘 | 落盘才算完成（`sessions.jsonl` 记 `quiz_answer`） |
| A6 | 用户说「下一章」才推进；**不主动连推** | 防疲劳弃用 |

### 节奏控制（新增，防弃用）

| 情形 | 处理 |
|---|---|
| 用户连续两章都大面积空白 | 提示「这本书前置难度可能超出当前水平」，建议先补前导章节或降档到模式 B 速览 |
| 用户答得又快又准 | 提高问题层级（定义 → 反例 → 反事实），别停在复述 |
| 用户说「跳过这章」 | 直接跳，不记账、不加罚，该章掌握度记 `skipped` |

## 3. 模式 B：直接生成文档（结构化速览）

### 触发

用户说「直接给我一份」「整理成文档」「先让我看看结构」「别问了」。

### 产出物（三件套，缺一不可）

| 文件 | 内容 | 落盘路径 |
|---|---|---|
| 结构化笔记 | 全书按章 → 节展开，每节含：核心问题 / 关键定义 / 公式或模型 / 一个例子 / 常见误解 | `atlas/<slug>/digest.md` |
| 可交互知识地图 | 现有 `build_atlas.py` 产出，节点带掌握度占位 | `atlas/<slug>/atlas.html` |
| 概念对照表 | 3–5 组易混概念两列对比 | 内嵌 `digest.md` 末节 |

### 与模式 A 的差异

模式 B **不要求**用户先回忆，直接产出。所以必须用**校验**替代「用户的检索动作」这个质量控制环节——见下一节。

### 使用约束（写进产出物头部，防误用）

生成的文档开头固定加一段：

> 这份是**速览**，不是学会。它省了你整理的时间，但没有替你建立记忆。
> 正确用法：合上它，先自己讲一遍这章讲什么 → 再打开对照漏了什么 → 从末尾的题目里抽 3 道闭卷答。

## 4. 生成前校验（用户明确要求的核心）

**原则：没有通过校验的内容不许交付。** 校验不是「我读一遍觉得挺好」，是五项可判定、可量化的检查。

### C1 · 覆盖率（可脚本计算）

- 取 `outline.json` 的全部节点（章/节/小节）
- 逐个在产出物文本中匹配该节点标题或其核心术语
- **未覆盖节点必须为 0**；覆盖率 < 100% 时，脚本列出缺失清单，补齐后重跑

### C2 · 断言溯源

- `digest.md` 中每条定义、公式、结论后面必须能定位来源：`[§3.2]` 或原文片段
- 无法溯源的，一律显式标注 **`（推断，非书中原文）`**，不许混在正文里冒充原文
- 脚本统计：可溯源比例、推断条数；**推断占比 > 20% 直接判不合格**

### C3 · 完整性三件套

对每个「核心概念」节点检查是否齐备：

| 检查项 | 缺了算什么 |
|---|---|
| 定义（是什么） | 不合格 |
| 公式/模型（怎么算） | 数学类必须有，否则不合格 |
| 一个具体例子（长什么样） | 不合格 |
| 适用条件/反例（什么时候不成立） | 重要概念必须有 |

### C4 · 一致性与矛盾检测

- 同一术语全书是否统一（如「特征向量」不许一半写「本征向量」）
- 同一概念前后的数值/条件是否冲突（如某定理在一处说「方阵」，另一处说「任意矩阵」）
- 交叉验证：公式与它配的例子是否自洽（代进例子算一遍）

**这一步必须真算。** 涉及数值的，用 Python 代入验证，不许眼过。

### C5 · 白纸复述测试（生成者的自检）

用一句话回答，答不上就是没吃透：

1. 这本书的核心问题是哪一个？
2. 全书的方法论主线是什么（作者用什么工具解决那个问题）？
3. 哪两章最容易被读者读成同一件事？
4. 如果只保留三章，删哪三章损失最小？

### 交付门槛

| 检查项 | 通过标准 |
|---|---|
| C1 覆盖率 | 100%，0 缺失 |
| C2 溯源率 | 可溯源 ≥ 80%，推断 ≤ 20% 且全部显式标注 |
| C3 三件套 | 核心概念 100% 齐备 |
| C4 一致性 | 0 处未解释的矛盾 |
| C5 复述 | 4 问全部答得出 |

**任一项不过 → 不许交付，先修再交。** 交付时附一张校验表（五项逐一打勾 + 具体数字），不是一句「已检查完毕」。

## 5. 模式选择规则（写进 SKILL.md 路由）

| 用户信号 | 走哪个模式 |
|---|---|
| 「带我啃」「问我」「一章一章」「别直接给我」 | A（对话式） |
| 「直接生成」「整理成文档」「先看看结构」「来不及」 | B（生成式） |
| 没表态 | **默认 A**，但第一句给选项：「要不要现在一章一章过，还是先出一份速览？」 |
| 说「先出速览，再一章一章过」 | B → A 接力：先交付带校验的文档，再按章进入对话式（文档当差集基准） |

**默认选 A 的理由**：A 的收益有实证支持（检索练习），B 只省时间。默认值应该站在收益那边。

### 6.1 为什么用「刁难样本」而不是等真实书

真实书验证一直卡在素材上：本机没有 EPUB 文件，Project Gutenberg 与 GitHub 的 release 下载都被阻断（`curl` 返回 000）。与其挂着不动，改成把**已知会让解析器出错的结构**逐个造出来：

| 造出来的结构 | 旧代码的行为 | 现在 |
|---|---|---|
| href 是 percent-encoding（`%E7%AC%AC%201%20…`） | `KeyError` → `continue`，**整章静默消失** | 先 unquote 再查；找不到打 `[warn] 已跳过` |
| 段落包在 `<div class="para">` 里 | 只认 `<p>`，**整章字数 0、正文全丢** | 认 div/td/blockquote 为块级容器 |
| 有 `META-INF/encryption.xml` | 抽出乱码还报"成功" | 检测加密目标是 xhtml/opf 就报错并给替代路径 |
| 四层标题（h1–h4） | h5/h6 丢失 | h1–h6 全收（层级压到 3 档，和导图一致） |

这些改动不依赖真实书，但覆盖了"真实书上最可能翻车"的几处。**仍未验证的是排版层**：标题用 `<div class="h1">` 而不用 `<h1>`–`<h6>` 的书，依然提不到标题——这种只能靠真实书撞上再改，README 的已知限制里写明了。

## 7. 实施后要回收的风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| B 模式被当成「学会」 | 用户拿到漂亮文档，主观感觉良好，实际零留存（PNAS 2025 同型现象） | 产出物头部强制声明 + 末尾固定 3 道闭卷题 |
| C1 覆盖率靠字符串匹配会误判 | 书中术语与标题不同（「第 3 章 线性变换」正文只写「变换」） | 已去掉编号再匹配（「1.2 基与维数」→「基与维数」），仍要求标题核心词出现；别名仍靠生成时人工补 |
| 校验表变成走过场 | 我自己给自己打勾 | 校验表的数字必须来自脚本输出，不手填；C4 数值类必须真代入算 |
| **把选择题正确率当成掌握度** | 80% 正确率听着很好，但那是识别，不是回忆 | 每章必留无选项题；`check_quiz.py` W6 抓"全章选择题"；偶数题追「为什么不是 X」，答不出记 `lucky` |
| 两套流程维护成本翻倍 | 改一处忘另一处 | 共用同一份 `outline.json` 与 `mastery.json`，只在「是否需要用户先答」上分叉 |

---

**一句话总结**：模式 A 是「学」，模式 B 是「取」；B 允许存在，但必须过五道校验，且不许冒充「学会了」。
