# 资源锚点 —— 给知识点挂一个"换个讲法"

> 起因：用户要求「问知识点时可以附带评论较好或观看量较多的视频/个人博客」。
> 这个需求本身合理——书上的讲法不合口味是真实痛点。但它踩在 AI 最容易出错的地方上：
> **编链接**。所以这份文件的重心不是"怎么给"，是"凭什么确定这条链接是真的、是好的"。

---

## 0. 一条不能破的底线

**不许凭记忆写链接。** 一个都不能。

理由不是"我可能会记错"，是实测过的：BV 号由 12 位字符组成，我随手造一个
`BV1xx411c7ZZ` 去查，B 站接口真的返回了一个视频——标题是「ウサウサvs荒巻」，
和线性代数毫无关系。

也就是说：**格式对、能打开、内容完全不相干**。这种错误比 404 更坏，因为用户会
点进去看三十秒才发现被骗，然后不再相信后面所有的推荐。

所以规则是流程性的，不是态度性的：

```
搜索 → 拿到候选 → resources.py add（走接口取真实数据）→ 核对返回的标题 → pick → 才能说
```

跳过任何一步，就不许在对话里出现这个链接。

## 1. 什么时候给（这一节最重要）

给链接有明确的副作用：它是**被动接收**，会替代用户自己想。所以时机比选哪条更重要。

| 时机 | 给不给 | 为什么 |
|---|---|---|
| 出题时、题目旁边 | ❌ **绝对不给** | 链接就是答案的入口，等于把题废了 |
| 用户正在尝试、还没交出任何东西 | ❌ | 会让他直接跳过去看，本轮就不再思考了 |
| 答完（对或错都算） | ✅ 章末一次给 | 此时检索动作已完成，给的是延伸不是替代 |
| 卡住，提示阶梯已走过第 1–2 层 | ⚠️ 可以给 | 但必须先走完指向层和框架层，不能一卡就给 |
| 用户主动问「有没有讲这个的视频」 | ✅ 直接给 | 不驳。这是他自己的策略选择 |
| 逃生阀触发（赶时间/敷衍/连续 3 轮无进展） | ✅ 直接给 | 见 `core-rules.md` §9 |

**一句话记法**：链接是**事后**的补充材料，不是**事中**的救援。唯一例外是用户自己开口要。

### 一次给几条

**最多 2 条**：1 条一手来源（如果需要查定义/API）+ 1 条视频。

给 5 条等于把选择成本转嫁给用户。他真正会点开的是第一条，剩下的只是让回复看起来丰富。

### 给的时候必须配一句话

不配这句话，看视频就退化成"重看一遍"，落在 Dunlosky 的低效用侧：

> 「看之前先猜一下：他会怎么解释 X？看完回来我要你闭卷答一遍，不管对错。」

或者更轻的版本：

> 「这条讲的是你没想通的那步。看完别急着说懂了，先说一句『他和我原来的想法差在哪』。」

## 2. 凭什么算"好"（判据都是工程阈值）

用户原话是"评论较好或观看量较多"。这两个词必须落成数字，否则只能凭感觉吹。

### 视频（B 站）

| 判据 | 门槛 | 为什么是它 |
|---|---|---|
| 播放量 | ≥ 5 万 | 低于这个是个人练习/搬运残片 |
| **收藏 / 点赞** | ≥ 0.6 | 知识类内容观众"留着以后用"才收藏；娱乐向点赞远多于收藏。**这条比播放量更能区分"有用"和"好听"** |
| **收藏 / 播放** | ≥ 1% | 搬运号、切片号播放高但几乎没人收藏 |
| 发布时间 | 超过 4 年标注提醒 | 原理类内容不受影响，工具/API/考纲类要核对 |

实测校准：宋浩《线性代数》那条播放 7786 万、收藏 142 万、点赞 152 万，
收藏/点赞 = 0.94，收藏/播放 = 1.83%——一条典型的合格样本。

> ⚠️ 这四个数字**全部来自接口**，不是我按印象填的。规则里也禁止在对话里说
> "这个视频播放量上百万"这种约数：要么报接口返回的精确值，要么不报。
> 报约数等于给自己留了编造空间。

### 一手来源（官方文档 / 论文原文 / 教材原书）

**不设流量门槛。** 文档没有人点赞，但它比任何视频都该先给。

要求只有两条：能打开、是这件事的原始出处（不是某篇转述）。

### 个人博客

| 判据 | 要求 |
|---|---|
| 作者 | 必须有署名。匿名博客不可引用 |
| 日期 | 必须有发布或更新年份 |
| 内容 | 与当前版本一致（版本类必须核对） |

优先顺序：作者本人的博客 > 长期维护的技术博客 > 平台专栏 > 其余。

## 3. 不该给什么（比"该给什么"更能省时间）

| 排除项 | 识别特征 |
|---|---|
| 搬运 / 切片 / 合集号 | 无原创出品、合集标题带「全集/合集」、简介引流私域 |
| 标题党 | 「10 分钟精通」「看完直接上岸」「99% 的人不知道」 |
| AI 配音 + PPT 朗读 | 全程一个音色念稿、无板书推导、画面只是文字 |
| 纯营销号 | 视频本身没内容，通篇在讲课程体系和价格 |
| 符号体系与用户教材不一致 | 教材用行向量、视频用列向量；教材记 `λ`、视频记 `k`。**初学者会被这层差异搞得更晕** |

最后一条容易忽略但很关键：**讲得对不对是一回事，和你的书对不对得上号是另一回事。**
遇到这种情况，给的时候必须说清楚：

> 「这条讲得清楚，但他用的是列向量记法，你书上用的是行向量。看的时候把这一层翻译过来，不然会更乱。」

## 4. 工具怎么用

资源库落在 `~/.study-os/resources/index.json`，和卡片、错题在同一个状态目录。

```bash
# 入库：B 站链接会自动走接口取播放/收藏/点赞，取不到就入库失败
python scripts/resources.py add --topic "线代/特征值" \
    --url "https://www.bilibili.com/video/BV1aW411Q7x1" \
    --note "特征值在第 42 讲左右，前 5 分钟是复习行列式" --evergreen

# 一手来源
python scripts/resources.py add --topic "python/列表推导" \
    --url "https://docs.python.org/3/tutorial/datastructures.html" \
    --kind primary --title "Python Tutorial - Data Structures" --evergreen

# 探活全库 + 刷新数字（数字每天都在变，别用旧数据下判断）
python scripts/resources.py probe

# 挑出能推荐的（不合格的不会出现）
python scripts/resources.py pick --topic 线代

# 看全库 / 按知识点统计
python scripts/resources.py list
python scripts/resources.py stats
```

`--note` 不要省。只说「这个视频讲特征值」没有用——用户点进去面对 60 集不知道看哪。
写到**第几讲 / 大概几分几秒 / 前面在讲什么**，这一栏才是真正节省时间的地方。

`--evergreen` 表示内容不随版本变化（数学原理、算法思想）。不标的话，
超过 4 年会被提醒"可能过时"，对原理类内容是误伤。

### 状态字段的含义

| 状态 | 意思 | 能不能推荐 |
|---|---|---|
| `ok` | 探活通过 | ✅ |
| `blocked` | 页面在，但拒绝脚本访问（403/418） | ✅ 但要自己点开确认一次 |
| `unreachable` | 这次连不上（网络问题，不代表链接坏） | ❌ 先别推 |
| `dead` | 404/410，真没了 | ❌ 永不推荐 |

`unreachable` 和 `dead` 必须分开：把网络问题判成失效，会把好链接一条条误删掉。

## 5. 这件事的证据边界

必须说清楚，否则"给链接"会被误当成学习手段。

- 视频、博客、讲解音频都属于**被动接收**。Dunlosky 2013 的高效用清单里没有它们；
  性质上更接近"听讲 / 重看"，而重看是低效用项。
- 没有任何证据说看视频有害。有证据说的是：**同样的时间花在闭卷回忆上，收益更高**
  （Karpicke & Blunt 2011）。
- 所以这个机制在本技能里的定位是：**解决"卡住时的理解障碍"，不是"学习方式"**。
  它的价值在于让用户跨过某个具体障碍，然后**回去继续检索**，而不是用观看替代检索。

对应到 `references/evidence.md` §4 的低证据等级条目。

> 说得再直白点：链接是止痛药，不是营养。痛的时候吃，不痛的时候别当饭吃。

## 6. 反模式

| 反模式 | 后果 |
|---|---|
| 每答完一题就甩一个链接 | 用户开始跳过思考直接等链接，本技能变成视频导航 |
| 报"播放量 100 万+"这种约数 | 给自己留了编造空间，且不可核验 |
| 只给链接不给位置 | 60 集的合集，用户点开就关 |
| 链接失效了还继续推 | 信任一次性消耗完 |
| 用热门度代替相关性 | 搜"线性代数"排第一的可能是考研冲刺课，跟当前这节无关 |
| 把"我搜到了"当成"我看过了" | 搜索结果摘要没有播放数，标题也可能与内容不符 |
